# servermonitor 部署文档

本文档说明如何部署 `servermonitor` TRSS-Yunzai 插件和服务器侧 agent。第一次安装可先看 `快速部署教程.md`。

## 1. 总体流程

```text
服务器 agent 采集指标  ──POST /servermonitor/report──>  TRSS-Yunzai 插件  ──渲染图片──>  管理员
```

部署顺序：

1. 在 TRSS-Yunzai 中安装 `servermonitor` 插件
2. 直接发送 `#服务器状态` 验证 Yunzai 本机状态输出
3. 需要监控其他服务器时，在 Yunzai 主人私聊中添加服务器并生成 token
4. 在目标服务器部署 agent
5. 再发送 `#服务器状态` 验证多机图片输出

## 2. Yunzai 端部署

### 2.1 放置插件目录

将整个目录复制到 TRSS-Yunzai 的插件目录：

```bash
cp -r servermonitor /path/to/Yunzai/plugins/servermonitor
```

目录结构应类似：

```text
/path/to/Yunzai/plugins/servermonitor/index.js
/path/to/Yunzai/plugins/servermonitor/server.js
/path/to/Yunzai/plugins/servermonitor/model.js
/path/to/Yunzai/plugins/servermonitor/local.js
/path/to/Yunzai/plugins/servermonitor/package.json
/path/to/Yunzai/plugins/servermonitor/config.example.yaml
/path/to/Yunzai/plugins/servermonitor/config.yaml    # 首次运行自动生成
/path/to/Yunzai/plugins/servermonitor/resources/server_status.html
```

### 2.2 重启或热加载

推荐先重启 Yunzai：

```bash
cd /path/to/Yunzai
pnpm start
```

如果你的 TRSS-Yunzai 支持热加载，也可以直接复制后等待插件热加载。

### 2.3 确认接口

插件会注册以下接口：

- `POST /servermonitor/report`：正式上报接口
- `POST /server-monitor/report`：兼容旧命名的别名接口

agent 默认使用：

```text
http://<Yunzai可访问地址>/servermonitor/report
```

> 注意：`cfg.server.url` 如果是 `127.0.0.1` 或 `localhost`，外部服务器无法访问，需要换成内网或公网地址。

## 3. 配置文件

配置文件位置：

```text
plugins/servermonitor/config.yaml
```

首次启动时插件会自动生成 `config.yaml`。你也可以手动复制示例配置：

```bash
cp plugins/servermonitor/config.example.yaml plugins/servermonitor/config.yaml
```

默认内容：

```yaml
admins: []
servers: []
page_size: 8
offline_timeout: 30
public_status: true
include_local: true
alert:
  enabled: true
  cooldown: 120
render:
  imgType: png
show_ip_in_image: false
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `admins` | 可查看状态的额外用户 ID，master 默认有权限 |
| `servers` | 已注册服务器列表，由 `#服务器状态添加` 自动维护 |
| `page_size` | 每张状态图显示的服务器数量 |
| `offline_timeout` | 超过多少秒没有上报判定为离线 |
| `public_status` | `true` 时任何人发送 `#服务器状态` 都会响应；`false` 时仅 master/admins 可查看 |
| `include_local` | `true` 时 `#服务器状态` 总览默认包含 Yunzai 本机卡片 |
| `alert.enabled` | 是否启用离线/恢复私聊通知主人 |
| `alert.cooldown` | 同类告警冷却时间，单位秒 |
| `render.imgType` | 渲染图片格式，支持 `png` / `jpeg` |

## 4. 本机状态验证

没有添加任何服务器时，发送：

```text
#服务器状态
```

插件会直接采集并展示 Yunzai 所在机器的本机状态，卡片名称为 `本机`。

添加其他服务器后，`#服务器状态` 会显示 `本机` 和各注册服务器，所有机器按名称分开成不同卡片。只看 Yunzai 本机可发送：

```text
#服务器状态 本机
```

如果总览中不想自动带上本机，可设置：

```yaml
include_local: false
```

## 5. 添加服务器

请使用主人私聊 Yunzai：

```text
#服务器状态添加 web-01
```

也可以加备注：

```text
#服务器状态添加 web-01 生产主站
```

机器人会返回：

- 服务器名称
- 上报 token
- 上报接口
- agent 启动命令

请妥善保存 token，不要发到群聊或公开日志中。

## 6. agent 部署

agent 位于：

```text
plugins/servermonitor/agent/
```

可以将 `agent/` 目录复制到每台目标服务器，例如：

```bash
mkdir -p /opt/servermonitor
cp -r agent /opt/servermonitor/agent
cd /opt/servermonitor/agent
npm install
```

### 6.1 测试采集

先做一次 dry-run，不上传：

```bash
node agent.mjs \
  --name web-01 \
  --token sm_xxx \
  --report-url http://yunzai.example.com/servermonitor/report \
  --dry-run
```

看到 JSON 输出即说明本机采集可用。

### 6.2 一次性上报

```bash
node agent.mjs \
  --name web-01 \
  --token sm_xxx \
  --report-url http://yunzai.example.com/servermonitor/report \
  --once
```

### 6.3 持续运行

```bash
node agent.mjs \
  --name web-01 \
  --token sm_xxx \
  --report-url http://yunzai.example.com/servermonitor/report \
  --interval 10 \
  --slow-interval 30
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `--name` | 服务器名，建议与 Yunzai 注册名一致 |
| `--token` | Yunzai 生成的上报 token |
| `--report-url` | Yunzai 上报接口 |
| `--interval` | 快速采集与上传间隔，单位秒，默认 10 |
| `--slow-interval` | GPU/磁盘/温度等慢指标刷新间隔，单位秒，默认 30 |
| `--timeout` | HTTP 上传超时，单位毫秒，默认 5000 |
| `--dry-run` | 仅输出采集快照，不上传 |
| `--once` | 上传一次后退出 |

## 7. Linux 部署

### 7.1 systemd 推荐方式

创建服务文件：

```bash
sudo vim /etc/systemd/system/servermonitor-agent.service
```

写入：

```ini
[Unit]
Description=servermonitor agent
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/servermonitor/agent
ExecStart=/usr/bin/node /opt/servermonitor/agent/agent.mjs --name web-01 --token sm_xxx --report-url http://yunzai.example.com/servermonitor/report --interval 10 --slow-interval 30
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now servermonitor-agent
sudo systemctl status servermonitor-agent
```

查看日志：

```bash
journalctl -u servermonitor-agent -f
```

### 7.2 Docker 可选方式

构建镜像：

```bash
cd /opt/servermonitor
docker build -t servermonitor-agent ./agent
```

运行：

```bash
docker run -d \
  --name servermonitor-agent \
  --restart always \
  --network host \
  --pid host \
  -v /proc:/host/proc:ro \
  -v /sys:/host/sys:ro \
  servermonitor-agent \
  node agent.mjs --name web-01 --token sm_xxx --report-url http://yunzai.example.com/servermonitor/report --interval 10
```

> Docker 模式下部分宿主机指标可能受容器隔离影响。若你需要最准确的主机指标，优先使用 systemd 原生部署。

## 8. Windows 部署

推荐方式：Node.js + NSSM。

### 8.1 安装依赖

1. 安装 Node.js 18+
2. 下载 NSSM：<https://nssm.cc/>
3. 将 `agent/` 目录放到 `C:\servermonitor\agent`
4. 执行：

```powershell
cd C:\servermonitor\agent
npm install
```

### 8.2 注册服务

```powershell
nssm install servermonitor-agent "C:\Program Files\nodejs\node.exe" "C:\servermonitor\agent\agent.mjs" --name web-01 --token sm_xxx --report-url http://yunzai.example.com/servermonitor/report --interval 10
nssm set servermonitor-agent AppDirectory "C:\servermonitor\agent"
nssm start servermonitor-agent
```

查看服务：

```powershell
nssm status servermonitor-agent
```

停止服务：

```powershell
nssm stop servermonitor-agent
```

## 9. macOS 部署

推荐使用 launchd。

假设 agent 在：

```text
/opt/servermonitor/agent
```

创建 plist：

```bash
sudo vim /Library/LaunchDaemons/com.servermonitor.agent.plist
```

内容：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.servermonitor.agent</string>

  <key>WorkingDirectory</key>
  <string>/opt/servermonitor/agent</string>

  <key>ProgramArguments</key>
  <array>
    <string>/usr/local/bin/node</string>
    <string>/opt/servermonitor/agent/agent.mjs</string>
    <string>--name</string>
    <string>mac-01</string>
    <string>--token</string>
    <string>sm_xxx</string>
    <string>--report-url</string>
    <string>http://yunzai.example.com/servermonitor/report</string>
    <string>--interval</string>
    <string>10</string>
  </array>

  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>

  <key>StandardOutPath</key>
  <string>/var/log/servermonitor-agent.log</string>
  <key>StandardErrorPath</key>
  <string>/var/log/servermonitor-agent.err</string>
</dict>
</plist>
```

加载：

```bash
sudo launchctl load -w /Library/LaunchDaemons/com.servermonitor.agent.plist
sudo launchctl list | grep servermonitor
```

卸载：

```bash
sudo launchctl unload -w /Library/LaunchDaemons/com.servermonitor.agent.plist
```

## 10. 验证

### 10.1 agent 上传日志

正常情况下会看到：

```text
[servermonitor-agent] web-01 uploaded @ 2025-01-01T00:00:00.000Z
```

### 10.2 Yunzai 侧查看

发送：

```text
#服务器状态
```

如果注册并上传成功，会返回状态图片。

## 11. 反向代理示例

如果通过 Nginx 暴露 Yunzai：

```nginx
location /servermonitor/ {
  proxy_pass http://127.0.0.1:2536/servermonitor/;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

建议额外配置：

- HTTPS
- IP 白名单
- 访问日志脱敏，避免泄露 token

## 12. 常见问题

### 12.1 显示“未上报”

检查：

1. agent 是否运行
2. `--report-url` 是否能从目标服务器访问
3. token 是否复制正确
4. Yunzai 是否能接收 HTTP 请求

### 12.2 GPU 数据为空

- NVIDIA GPU 需要 `nvidia-smi` 可用
- 非 NVIDIA GPU 目前主要展示系统能识别到的型号，利用率/功耗可能为空

### 12.3 温度或功耗为空

这属于平台能力差异：

- CPU 温度依赖系统传感器能力
- Linux CPU 功耗优先读取 Intel RAPL
- GPU 功耗优先读取 `nvidia-smi`
- Windows/macOS 部分指标可能不可用

### 12.4 离线误判

适当调大：

```yaml
offline_timeout: 60
```

同时保证 agent 的 `--interval` 小于 `offline_timeout`。

## 13. 升级

1. 停止 agent
2. 替换 Yunzai 插件文件
3. 保留 `config.yaml` 和 `data/snapshots.json`
4. 重启 Yunzai
5. 重新启动 agent

## 14. 卸载

1. 停止各服务器 agent
2. 删除 Yunzai 中 `plugins/servermonitor/`
3. 重启 Yunzai
