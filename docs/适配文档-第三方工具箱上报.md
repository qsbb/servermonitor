# 第三方工具箱适配文档：上报到 TRSS-Yunzai servermonitor

> 面向：想把本机状态接入 Yunzai `#服务器状态` 的任意 Windows/Linux 工具箱、脚本、客户端开发者。
> 本文所有行为均已对照插件源码（`model.js`）逐条核实，可直接作为接入契约使用。

## 1. 目标

工具箱按固定间隔把本机状态 POST 到 Yunzai 的 `servermonitor` 插件 HTTP 端点，插件在 `#服务器状态` 渲染这台机器（CPU/内存/磁盘/网络/在线状态）。

## 2. 接口契约

| 项 | 值 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/servermonitor/report` |
| Content-Type | `application/json` |
| 认证头 | `X-SM-Token: <token>`（≤128 字符） |
| 请求体上限 | stock TRSS 全局 JSON 解析器默认 100 KB 先生效；插件自身 256 KB 为第二道防线，超出返回 413 |
| 单 token 限速 | 60 次/分钟（按 token+IP 计） |
| 单 IP 限速 | 240 次/分钟（所有 token 合计） |
| 离线判定 | `offline_timeout` 秒（默认 30）无上报即离线——**上报间隔必须 < 此值**，建议 10~20 秒 |
| 时间基准 | 上报到达时刻为准；`agent_ts` 仅作展示，可省略 |

```text
POST http://192.168.5.88:2536/servermonitor/report
X-SM-Token: sm_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json
```

## 3. 独立 token 流程（共享 token 已停用）

> 共享 token 无法区分主机，已在当前开发版停用；携带旧 `shared_token` 的上报返回 `401` 和迁移提示。
> 存量自动注册节点可在 Yunzai 主人私聊执行 `#服务器状态命令 <名称>`，取回它已有的独立 token 和启动命令。

### 路径 A：Yunzai 先生成 token（服务端登记）

1. 在 Yunzai 主人**私聊**里发送：`#服务器状态添加 <名称> [上报地址] [备注]`，得到独立 token；地址可填站点根地址或完整接口
2. 工具箱用该 token 上报；因为服务器已登记，直接返回 `200`
3. 之后正常收数；可用 `#服务器状态命令 <名称>` 再次获取 token 和启动命令

### 路径 B：工具箱先生成 token（先上报后绑定）

1. 工具箱生成 `sm_` + 32 位十六进制 token
2. 工具箱用该 token 上报；首次上报后服务端保存待绑定记录并返回：

```json
{ "ok": true, "pending": true, "name": "toolbox-win-01", "bind": "#服务器状态绑定 sm_xxx…" }
```

3. 在 Yunzai 主人私聊发送返回的 `bind` 命令完成绑定；之后正常收数

也可以先上报再绑定：`#服务器状态待绑定`（master 私聊）列出所有待绑定 token，逐个 `#服务器状态绑定 <token>`。

> 好处：一台机器一个 token，name 冲突与删除互不影响，`#删除服务器 <名称>` 即可下线一台。

## 4. `name` 清洗规则（务必遵守）

服务端会对 `name` 做如下清洗（`sanitizeServerName`），**清洗后必须仍非空**：

- 删除字符：`< > & " ' \` \\`（正斜杠 `/` 保留）
- 连续空白 → 单个下划线 `_`
- 截断到 32 字符

建议直接用 `机器名-序号` 形式（如 `toolbox-win-01`），只含字母数字、`-`、`_`，永远安全。

## 5. 请求体结构（协议 v:1）

```json
{
  "v": 1,
  "name": "toolbox-win-01",
  "agent_ts": 1710000000000,
  "os":     { "platform": "windows", "distro": "Windows 11 Pro", "release": "22H2", "arch": "x64", "hostname": "DESKTOP-XXXX", "uptime": 123456 },
  "cpu":    { "model": "Intel Core i7-12700", "cores": 12, "usage": 37.5, "temp": 62, "power": null },
  "gpus":   [{ "model": "NVIDIA GeForce RTX 3060", "usage": 55, "temp": 65, "memUsed": 2.4, "memTotal": 12, "power": 120 }],
  "mem":    { "used": 8.2, "total": 16, "available": 7.8, "swapUsed": null, "swapTotal": null },
  "net":    { "iface": "Ethernet", "rxSec": 12.3, "txSec": 4.5, "rxTotal": 1024.5, "txTotal": 512.1 },
  "disks":  [{ "mount": "C:\\", "used": 120.5, "total": 512 }],
  "load":   null
}
```

字段规则：

- `v` 必须是数字 `1`
- `name` 唯一且稳定（服务端以 name 为机器键）
- `os/cpu/mem/net` 整块可为 `null`；`gpus/disks` 可为空数组
- **全空白快照会被 422 拒收**（`empty snapshot`）——至少给 `cpu.usage` 或 `mem` 一项
- 数值一律传纯数字（不带单位字符串）：
  - 温度：摄氏度；显存/内存/磁盘：GB；速率：MB/s
  - `load`：`[1,5,15]` 分钟负载数组；**Windows 一律传 `null`**，UI 会隐藏
- `cpu.temp`/`cpu.power`/`gpus[].usage|temp|power` 等不可得字段传 `null`（服务端容忍缺列）
- `mem.available` 是可选字段，表示可立即供新进程使用的估计内存，单位 GB；Linux 推荐对应 `/proc/meminfo` 的 `MemAvailable`
- 服务端有合法 `available` 时按 `total - available` 显示内存压力；字段缺失或为 `null` 时回退 `used`，旧工具无需强制升级
- 不要用 `total - used` 反推 `available`；这会把包含 page cache 的旧统计重新包装成新字段

## 6. 最小可用请求

```json
{
  "v": 1,
  "name": "toolbox-win-01",
  "os":   { "platform": "windows", "hostname": "DESKTOP-XXXX" },
  "cpu":  { "model": "Intel Core i7-12700", "usage": 30 },
  "mem":  { "used": 8, "total": 16 },
  "disks": [{ "mount": "C:\\", "used": 100, "total": 512 }]
}
```

## 7. Windows 快速自测（PowerShell）

```powershell
$token = "sm_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
$body = @'
{
  "v": 1,
  "name": "toolbox-win-01",
  "os": { "platform": "windows", "hostname": "DESKTOP-XXXX" },
  "cpu": { "model": "Intel Core i7-12700", "usage": 30 },
  "mem": { "used": 8, "total": 16 },
  "disks": [{ "mount": "C:\\", "used": 100, "total": 512 }]
}
'@

Invoke-RestMethod -Uri "http://192.168.5.88:2536/servermonitor/report" -Method Post `
  -Headers @{ "X-SM-Token" = $token } `
  -ContentType "application/json" `
  -Body $body
```

返回解读：

- 已登记独立 token 成功：`{ "ok": true, "name": "toolbox-win-01", "auto": false }`
- 未登记的独立 token 首次成功（待绑定）：HTTP 202 + `pending: true` + `bind` 命令
- 旧共享 token：HTTP 401 + `msg: "shared token disabled"` 和迁移提示
- 失败：见下表

## 8. 状态码总表

| HTTP | 场景 | 含义与排查 |
| --- | --- | --- |
| 200 | 已登记独立 token | 成功；确认返回 `name` 是你要的 |
| 202 | 未登记的独立 token 首次上报 | 已入待绑定队列；到 Yunzai 私聊发送返回的 `bind` 命令 |
| 401 | token 无效 / 格式不合法 / 旧共享 token 已停用 | 使用 `sm_` + 32 位十六进制独立 token；旧节点执行 `#服务器状态命令 <名称>` 迁移 |
| 413 | 请求体超过宿主上限 | stock TRSS 全局 JSON 上限为 100 KB；减少 gpus/disks 条数 |
| 422 | schema/内容错误 | `v` 非 1、JSON 不合法、数值带单位字符串、全空快照、token > 128 字符 |
| 429 | 限速或待绑定队列已满 | 单 token 60 次/分、单 IP 240 次/分、待绑定创建 10 次/分；降低频率或先清理待绑定 |
| 500 | 服务端异常 | 看 Yunzai 控制台/日志 |

## 9. 排查顺序

1. Windows 上先用第 7 节 PowerShell 发一次——200/202 即接口链路通，问题在工具箱自身
2. 非 200/202：对照第 8 节状态码表，把返回体和请求体贴给插件维护者
3. Yunzai 侧日志确认：

   ```bash
   tail -n 200 logs/command.$(date +%F).log | grep -i servermonitor
   ```

   正常应看到 `report accepted: name=… token=...xxxx shared`（共享）或 `report pending saved`（待绑定）
4. Yunzai 里发 `#服务器状态列表` 确认机器出现；`#服务器状态` 查看渲染效果
5. 独立 token 流程卡住时：`#服务器状态待绑定`（master 私聊）看队列

## 10. Windows 采集命令参考

```powershell
# CPU 型号/使用率
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfLogicalProcessors, LoadPercentage
# 内存（KB → GB 需 /1MB）
Get-CimInstance Win32_OperatingSystem | Select-Object TotalVisibleMemorySize, FreePhysicalMemory
# 磁盘（DriveType=3 固定盘；字节 → GB 需 /1GB）
Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" | Select-Object DeviceID, Size, FreeSpace
# GPU 型号（usage/temp 需 nvidia-smi 或厂商 SDK，拿不到就传 null）
Get-CimInstance Win32_VideoController | Select-Object Name, AdapterRAM
# 网卡统计（字节，两次采样差值 / 秒 → MB/s）
Get-NetAdapterStatistics
```

> .NET 工具箱可直接参考现成实现：[凌溪工具箱 `SystemMetricsCollector`](https://github.com/qsbb/lingxi-toolbox/blob/master/src/LX.Monitor.Core/Reporter/SystemMetricsCollector.cs)（WMI + PerformanceCounter + NetworkInterface，协议 v:1 完整字段，失败退避重试）——它正是按本文档契约开发的。

## 11. 上报器行为建议

- **间隔**：固定 10 秒（与官方 agent 默认一致），任何环境下都远低于 30 秒离线阈值
- **失败退避**：失败后指数退避（1s→2s→…→30s 封顶），恢复成功即回正常间隔——避免雪崩时打满限速
- **超时**：单次请求 5 秒超时，超时视为失败走退避
- **User-Agent**：建议带 `工具箱名/版本`，便于服务端日志定位
- **采集成本**：WMI 查询较贵，静态信息（CPU 型号/内存总量/OS）缓存 5 分钟，动态指标（usage/网速）每次取
- **时钟**：`agent_ts` 用本机毫秒时间戳即可；服务端按到达时刻判活，时钟偏差无影响

## 12. 集成清单

- [ ] `POST` 到 `/servermonitor/report`，`Content-Type: application/json`
- [ ] `X-SM-Token` 头已带上（必须是 `sm_` + 32 位十六进制独立 token）
- [ ] `v` 是数字 `1`；`name` 唯一、稳定、过清洗规则（第 4 节）
- [ ] 数值字段全是数字（无单位字符串）；Windows 下 `load: null`
- [ ] 能提供可信可用内存时传 `mem.available`；不能提供时省略或传 `null`
- [ ] 快照至少含一项动态指标（防 422 空快照）
- [ ] 上报间隔 ≤ 30 秒（建议 10 秒）；失败退避
- [ ] Yunzai 日志出现 `report accepted` 或 `report pending saved`
- [ ] `#服务器状态列表` 能看到机器；`#服务器状态` 渲染正常

## 13. Yunzai 侧指令速查（master 私聊为主）

| 指令 | 权限 | 作用 |
| --- | --- | --- |
| `#服务器状态` / `#服务器状态 <名称>` | 所有 | 状态总览 / 单台详情 |
| `#服务器状态列表` | 所有 | 已注册机器列表 |
| `#服务器状态帮助` | 所有 | 帮助 |
| `#服务器状态命令 <名称>` | master 私聊 | 重新获取该机器的独立 token 和启动命令 |
| `#服务器状态令牌` | master | 已停用，返回迁移说明 |
| `#服务器状态添加 <名称> [上报地址] [备注]` | master | 创建机器并生成独立 token，可指定工具实际访问的上报地址 |
| `#服务器状态绑定 <token>`（或 `<名称> <token>`） | master | 绑定待上报的 token |
| `#服务器状态待绑定` | master 私聊 | 列出待绑定队列 |
| `#服务器状态改名 <旧名> <新名>` / `#删除服务器 <名称\|序号>` | master | 管理机器；无参数的 `#删除服务器` 会列出服务器 |

## 14. 给协作方的接入提示词（直接复制）

> 请按以下契约接入 Yunzai servermonitor：
>
> 1. `POST http://192.168.5.88:2536/servermonitor/report`，头 `X-SM-Token: <token>`、`Content-Type: application/json`。
> 2. 请求体 JSON 至少：
>    ```json
>    { "v": 1, "name": "toolbox-win-01", "os": { "platform": "windows", "hostname": "DESKTOP-XXXX" },
>      "cpu": { "usage": 30 }, "mem": { "used": 8, "total": 16 },
>      "disks": [{ "mount": "C:\\", "used": 100, "total": 512 }] }
>    ```
>    数值必须是数字；`name` 全局唯一、≤32 字符、不含 `<>&"'`\\`、空格会被替换为 `_`。
> 3. 间隔 10 秒（不得超 30 秒，否则判离线）；失败指数退避 1s→30s；单次超时 5 秒。
> 4. 验证：先 PowerShell `Invoke-RestMethod` 手发一次，期待 200（已在 Yunzai 登记的独立 token）或 202（未登记 token，按返回的 `bind` 命令去 Yunzai 私聊绑定）；再进代码。
> 5. 错误对照：401 token 错/格式不合法/共享 token 已停用；422 结构或空快照；429 限速或待绑定队列满；413 体积超过宿主上限。
> 6. 全字段参考：凌溪工具箱的 `SystemMetricsCollector`（github.com/qsbb/lingxi-toolbox）。
